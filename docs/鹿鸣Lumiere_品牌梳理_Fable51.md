## 1. 一句话诊断

**名字已经统一了，但「人」还没统一：三个平台是三个不同的人在说话——小红书是文艺创作者（卡通头像 + 「偶尔掉落」），公众号是极客（代码底实拍 + 「工作台」），X 还是空白。别人看三次，记不住一个。**

拆开看，截图暴露的三个具体问题：

1. **身份口径不一致。** 小红书简介「在真实与像素之间，收集灵感，驯养工具」是爱好者语气；公众号简介「把新东西放到工作台上」是从业者语气。定位已经定为「商业摄影师 / AI 制片」，只有后者对。
2. **视觉不一致。** 图 1 是暖黄底卡通头像，图 2 是紫蓝代码底实拍。眼镜是唯一共同点。头像是跨平台识别的第一资产，现在等于没有。
3. **信号错位。** 小红书「2162 关注 / 226 粉丝」——关注数是粉丝数近 10 倍，这是「学习者账号」的形态，不是「从业者账号」的形态。内容里最高赞的是**工具帖**（火烧云预测 204 赞），恰好就是定位要的那种东西，但简介没有承接它。

结论：这次梳理的核心不是「起名」，是**把三个账号收成同一个人**。

## 3. 视觉统一

### 3.1 头像：一张实拍，三处同图

**决策：用实拍，不用卡通、不用 AI 生成人像。** 理由只有一条——定位是商业摄影师，头像本身就是作品。用户本人出片，Lovart 不参与头像。

拍摄要求（给自己下的 brief）：

- **场景**：工作台。桌面、显示器边缘或镜头前景可以虚化入镜，呼应文案母题。
- **光**：暗背景 + 单侧暖色主光（琥珀/橙），面部有明显明暗过渡。要「发光」的感觉，不要平光。
- **人物**：戴眼镜，正面或 3/4 侧，直视镜头，**不遮脸、不拿杯子**（杯子会让人联想到咖啡线）。中性偏笃定的表情，不笑得太开。
- **构图**：头肩像，头部占画面高度 55–65%，为圆形裁切留余量。
- **输出**：一张主图，导出三个尺寸：正方形 1:1（小红书 / 公众号 / X 通用），另存 400×400 与 1000×1000 两版。**三个平台用同一张、同一裁切。**

### 3.2 色彩与字体

| 元素 | 定案 |
|---|---|
| 主色 | 深炭黑 / 近黑背景 |
| 强调色 | 暖琥珀（承接「发光」+ 霞光雷达的火烧云色系） |
| 辅助色 | 一点电子青，只用于「Agent / 工作流」类信息的点缀，占比不超过 10% |
| 中文字体 | 一款无衬线黑体，全平台封面统一 |
| 西文字体 | 一款几何无衬线，用于「Lumiere」字标 |

不要紫蓝代码底（图 2 那种）。它属于「程序员」视觉，不属于「摄影师用 AI」。

### 3.3 字标与横幅

- **字标**：「鹿鸣Lumiere」一行排版即可，中文略大、西文略小。**不做鹿的图形 logo**，现阶段任何吉祥物都会把品牌拉向「IP 化」，与从业者定位相反。
- **X 横幅（1500×500）**：用 Lovart 生成或用自己作品拼版。内容三选一，按优先级：① 一张自己拍的暗调暖光工作台实景；② 霞光雷达界面截图 + 一张自己拍的晚霞并置；③ 纯色深底 + 字标 + 一行英文 tagline。不放人像（头像已经是人像）。
- **公众号**：没有横幅位，但有三处视觉出口——文章头图模板、菜单栏、关注后自动回复里的二维码图。三处沿用同一套色板与字标。
- **二维码**：从公众号后台「下载二维码」拿带「搜一搜」标识的版本，放进 X 横幅右下角**不做**（X 用户扫公众号码路径太长），只用于公众号文章尾部与小红书图片末页。

### 3.4 Lovart 的使用边界

Lovart 只做：横幅、封面模板、色板示意、字标排版。**不做**：头像、任何「我本人」的形象、任何要冒充实拍的图。摄影师账号里出现 AI 假实拍，是一次性透支信用。

### 4.2 评价

**整体：过关，可以直接用。** 三行结构清晰——身份 / 关键词 / 态度，长度远在 160 字符限制内，中英混排在 X 的中文创作者语境里是常规做法。

逐行：

| 行 | 评价 | 备注 |
|---|---|---|
| 商业摄影师｜AI制片 | 好。全角竖线比斜杠更稳，两个身份并列不分主次，符合「摄影师用 AI」的定位 | 不加「独立」「资深」之类修饰 |
| AI video workflow · digital human · Agents | 好。这一行是给搜索和英文用户看的，三个词恰好对应三条内容线。间隔点比逗号干净 | 「Agents」复数与前两个单数不对称，可接受；若强迫症，改「Agent workflows」会和第一个词重复，不如保持现状 |

### 4.3 未定字段建议

| 字段 | 建议 |
|---|---|
| 地点 | `Guangzhou` |
| 网站 | 优先霞光雷达在线 Demo（`sunset-radar.pages.dev`），其次 GitHub 主页。理由：这是唯一能让陌生人 30 秒内验证「可复现工作流 + Agent」的东西。**不放公众号二维码页、不放小红书主页链接** |
| 头像 | §3.1 统一实拍 |
| 横幅 | §3.3 |
| 置顶 | 默认不发帖，所以**不做置顶**。空账号 + 完整资料 + 外链是一个「已注册、有出处」的状态，比一条勉强的开场帖强 |

### 4.4 一个命名风险要知道

「Lumiere」在 AI 语境下有一个已知重名：Google 曾以 Lumiere 命名过一个视频生成模型。这意味着在 X 上单搜「Lumiere AI」会被别人的结果淹没。**应对不是改名**，而是：

- 展示名永远带「鹿鸣」，不单独出现「Lumiere」；
- 用户名 lumierebyai 里的「by ai」本身已经是区分；
- 所有对外自称写「鹿鸣Lumiere」全称。

## 5. 小红书 / 公众号 优先级

### 5.1 小红书：第一优先级（修资料，不改内容策略）

它是三个平台里唯一有存量（226 粉丝、5+ 篇笔记、最高赞 204）的地方，修一次资料，存量立刻兑现。

**动作（一次完成，10 分钟）**

1. 头像：换统一实拍。
2. 简介：替换为已定文案——

   ```
   左手镜头，右手 AI。
   把新东西放到工作台上，看它到底能不能发光。
   商业摄影师 / AI 制片。工作流、数字人、Agent。
   ```

   第一行是从旧简介里唯一值得保留的句子，已经在文案里了。
3. 属地 / 城市：保持「广东广州」。年龄「36岁」显示与否不影响，按个人意愿。
4. 小红书号：AwesomeLab **不动**。
5. 关注列表：按 §2.2 分批清理。
6. 收藏页：检查是否公开。若公开，里面若有咖啡 / 柯森相关内容，转私密。

**内容口径（不是要发帖，是为将来发帖时定标准）**

- 每篇笔记必须带**一个可复现的东西**：一段步骤、一个参数、一个仓库链接、一条工作流图。没有就不发。
- AI 写真类内容不砍，但换框架：从「看我生成了什么」变成「摄影师视角：这套写真是怎么用工作流做出来的」。
- 不写「XX 模型炸了」「XX 又更新了」类热点帖；不发纯提示词清单。

### 5.2 公众号：第二优先级（补白 ≠ 起更新节奏）

「补白」的定义：让一个陌生人点进来时，**觉得这个号有人在、有东西、知道它是谁**。不需要日更、周更，需要以下五件事一次做完。

**动作**

1. **头像**：统一实拍。
2. **简介**：确认为已定文案——

   ```
   把新东西放到工作台上，看它到底能不能发出光芒。
   商业摄影师、AI 制片。写可复现的工作流：数字人口播、Agent 用法、模型实测。
   ```

3. **视频号名称**：从「鹿鸣lumiere」改为「鹿鸣Lumiere」（若平台允许）。
4. **关注后自动回复**：一段话 + 一个链接。建议——

   > 你好，我是鹿鸣Lumiere，商业摄影师、AI 制片。这里写可复现的工作流。先从这个开始：霞光雷达——我用 Agent 造的火烧云预测工具，代码开源，链接 → [仓库或 Demo 地址]

5. **菜单栏**（三个一级菜单，不做二级）：
   - 「工作流」→ 指向压舱文（见下）
   - 「工具」→ 指向霞光雷达 Demo
   - 「关于」→ 一篇 300 字以内的自我介绍文（可与压舱文合并为一篇，菜单先指同一篇）
6. **一篇压舱文**：把本仓库 README + `docs/algorithm.md` + `PROMPT.md` 改写成一篇「我怎么用 Agent 做了一个火烧云预测工具，以及你怎么复刻」。素材已全部在仓库里，改写成本最低、最贴定位。**这是补白，不是第一篇周更。**发完可以停。
7. **不做**：微信认证、商品展示、原创声明之外的任何「运营功能」。

### 5.3 为什么这个顺序

小红书有存量，改一次资料等于给 226 个已关注者重新自我介绍；公众号没有存量，做得再好也是从零起步，但它是唯一能承载长文、可被搜一搜索引的地方，所以第二。X 排第三：资料填满后**停在那里**。

## 6. 七天清单

每天一件事，每件事有完成标准。总投入约 6–8 小时，集中在 Day 1 和 Day 5。

| 天 | 动作 | 完成标准 |
|---|---|---|
| **Day 1** | 拍头像。按 §3.1 brief 自拍或请人按 brief 拍。挑 1 张，导出 1:1 三个尺寸 | 三个平台可直接上传的同一张图，放在一个文件夹里 |
| **Day 2** | 小红书资料全部更新（§5.1 动作 1–4、6）；开始清关注列表（第一批） | 主页截图与已定文案逐字一致；关注数开始下降 |
| **Day 3** | X 资料全部填满（§4）；Lovart 出横幅（§3.3）；网站字段指向霞光雷达 Demo | 主页无空字段；不发帖 |
| **Day 4** | 公众号资料：头像、简介确认、视频号改名、自动回复、菜单栏（先指向 Demo 与占位）| 陌生人关注后能收到自动回复并点到 Demo |
| **Day 5** | 写公众号压舱文（§5.2 动作 6）。素材：README、algorithm.md、PROMPT.md。配图用自己拍的晚霞 + 界面截图 | 一篇 1500–2500 字文章发出，菜单「工作流」「关于」指向它 |
| **Day 6** | 交叉校验：三个平台展示名写法、头像、属地、外链逐项对照；小红书收藏页隐私检查；确认无任何咖啡线痕迹 | 一张三列对照表，全部打勾 |
| **Day 7** | 冻结。把三套文案、色板、头像文件、横幅源文件归档到一个「品牌资产」文件夹。之后 30 天不再改资料 | 文件夹存在，且你不再打开任何一个平台的「编辑资料」 |

**Day 7 的「冻结」是清单里最重要的一项。**资料反复改的账号，比资料略有瑕疵的账号更不可信。

## 7. 不要做清单

1. **不要改名。**不用 Lumia，不加副名，不加 emoji，不在展示名后缀「AI」「Lab」「Studio」。
2. **不要动小红书号 AwesomeLab。**改号次数受限，且现阶段收益为零。
3. **不要在 X 发帖。**包括「大家好」类开场帖。资料填满即止。
4. **不要用 AI 生成头像或任何冒充实拍的人像。**摄影师账号的底线。
5. **不要做鹿的吉祥物 / 图形 logo。**字标够用。
6. **不要三个平台用三张不同头像。**哪怕是同一次拍摄的不同角度也不行。
7. **不要写「AI 博主」「AIGC 创作者」「独立开发者」。**你是商业摄影师和 AI 制片，其他都是手段。
8. **不要追模型发布、不要发提示词合集、不要做「一周 AI 新闻」。**已定的内容红线。
